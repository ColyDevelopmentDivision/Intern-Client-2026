## TODO①：レアリティで演出を出し分ける

### ヒント1（どこを・何を見る？）

書き換えるのは `PlayResultEffect` メソッドの中の `effects.PlayCommon();` の1行だけです。
このメソッドは**カードを1枚めくるたび**に呼ばれていて、引数の `rarity` に**そのカードのレアリティ**
（`Rarity.R`／`Rarity.SR`／`Rarity.SSR` のどれか）が入ってきます。
つまり「`rarity` の値によって、呼ぶ演出メソッドを変える」処理を書けばOKです。

### ヒント2（使う道具）

値によって処理を分けるには `switch` 文が使えます。一般形はこれ：

```csharp
switch (調べたい値)
{
    case 値A:
        値Aだったときの処理;
        break;
    case 値B:
        値Bだったときの処理;
        break;
    default:
        どれでもなかったときの処理;
        break;
}
```

- レアリティと比べる値は `Rarity.SSR` のように書きます
- 各 `case` の最後の `break;` を忘れずに（忘れるとエラーになります）

### ヒント3（骨組み）

ここまで書ければ、あとは3つの演出メソッドをどこに入れるかだけ：

```csharp
switch (rarity)
{
    case Rarity.SSR:
        // ここで一番派手な演出を呼ぶ
        break;
    case Rarity.SR:
        // ここで中くらいの演出を呼ぶ
        break;
    default: // どれでもない＝R
        // ここで控えめな演出を呼ぶ
        break;
}
```

使える演出は `effects.PlayCommon()`／`effects.PlayRare()`／`effects.PlaySpecial()` の3つです。

## TODO②：めくる直前の“予兆”

### ヒント1（どこを・何を見る？）

書く場所は `RevealRoutine` メソッドの中、**TODO②のコメントがある位置**（`ShowCard` の前＝カードをめくる直前）です。
「このカードのレアリティが高いか？」は `item.rarity` で調べられます。
つまり「`item.rarity` が高いときだけ、予兆演出を呼ぶ」`if` 文を1つ書きます。

### ヒント2（条件の作り方と、特別な呼び方）

- `Rarity` は **R → SR → SSR の順**に定義されているので、**不等号で比較できます**。
  例えば「SR以上」は `item.rarity >= Rarity.SR` と書けます。
- 予兆演出のメソッドは `effects.PlayOmen()`。ただし普通の呼び方ではなく、
  **`yield return effects.PlayOmen();`** と書きます（“溜め”の時間だけ、めくる処理を待たせる呼び方です）。

### ヒント3（骨組み）

```csharp
if (item.rarity >= /* どのレアリティ以上で予兆を出す？ */)
{
    yield return effects.PlayOmen();
}
```

「SR以上」にするか「SSRだけ」にするかは自分で決めましょう（正解は1つじゃありません）。

## TODO③：予兆の色をランダムに

### ヒント1（どこを・何を見る？）

変えるのは**TODO②で書いた `if` の中の1行だけ**です。
`PlayOmen` には**番号を渡せる版** `PlayOmen(パターン番号)` が用意されていて、
0〜2 の番号で予兆の色が変わります（0=金／1=紫／2=水色）。

### ヒント2（ランダムな数字の作り方）

- ランダムな整数は `Random.Range(0, 3)` で作れます。**0・1・2 のどれか**が返ります（**3は含まれません**）
- 作った数字はいったん `int` の変数に入れてから渡すと読みやすいです

### ヒント3（骨組み）

```csharp
int pattern = /* 0〜2 のランダムな数字を作る */;
yield return effects.PlayOmen(pattern);
```

⚠️ `yield return` はTODO②のときのまま**必ず残す**こと。消すと予兆がまったく出なくなります。

## 発展課題：ガチャの種類を増やす

### ヒント1（発想の転換）

この課題では**コードを1行も書きません**。
「ガチャ1つぶんの情報」がどこにあるかを探しましょう——Project ウィンドウで `Assets/MasterData` フォルダを開き、
`GachaTable_1_通常ガチャ` をクリックして Inspector を見てください。
バナーに出る名前も、コストも、出てくるキャラのリストも、**ぜんぶこのアセット（データ）に入っています**。

### ヒント2（自分のガチャを作る）

- アセットは選択して **Ctrl+D** で複製できます
- 複製したら名前を変え、Inspector で中身を自分の企画に書き換えます：
  - `Gacha Id` … 既存（1・2）と**被らない数字**に（例：3）
  - `Gacha Name` … バナーに表示される名前
  - `Cost Amount` … 1回引くのに必要な石の数
  - `Entries` … 出てくるキャラのリスト。**上から並べた順＝そのまま出る順**です（今日は登録順の固定結果）。
    `itemId` は課題シートの一覧（2001〜2010）から選ぶこと

### ヒント3（ゲームに登録する）

作ったアセットは、まだゲームに「開催中のガチャ」として登録されていません。登録場所は：

1. `Assets/Scenes/GachaTopScene` を開く
2. Hierarchy で `GachaTopSceneFlow` オブジェクトを選択
3. Inspector の **Gacha Tables** 配列のサイズを1つ増やし、増えた欄に自分のアセットをドラッグ＆ドロップ
4. Play → バナーは**登録した数だけ自動で並ぶ**ので、これだけで完成です

### うまくいかないときは

| 症状 | 見直すところ |
|---|---|
| バナーが増えない | Gacha Tables 配列に入っているか／開いているシーンは GachaTopScene か |
| 引いても何も出ない | `Entries` が空のまま（Console にエラーが出ています） |
| Console に「itemId=xxxx が見つかりません」 | 一覧（2001〜2010）にない番号を入れている |
| バナーを押しても引けない（警告ログ） | `Cost Amount` が所持石（100,000）より大きい |
